STEP 1 · 取证 B

设计 DNA = 色彩结构 + 签名公式 + 精确计数

① 色彩 → token 体系
吸管取 30 个色值 → 归纳出结构：
1 主色 amber + 4 扇区色 + 6 中性色
--accent-amber:#f2a93c · --bg:#0a0a0c …
发现「体系」比收集「色值」重要 100 倍
② 签名公式（可参数化）
辉光 = 一个公式吃任意主色：
box-shadow: 0 0 Npx −Mpx
  color-mix(in oklab, accent 75%, transparent)
凡是「最抓眼的效果」，都要写成 公式 + 参数，而不是一次性 CSS
③ 精确计数
环形组件 30 段、每区 6 段、60s 一圈、拖尾 32°
—— 全部来自逐帧测量，一个都不能「大概」

阶段 06 · 匀速三档

「太快了，而且不是匀速的」——一条指令揪出二次方加速 bug

「TheDial 现在呈现的效果就是我想要的，但是转动速度太快了，而且不是匀速的， 请按照 60 秒、30 秒、10 秒转一圈来设计」
先确认「对」，再修「快」—— 需求颗粒度教科书
根因：每帧回写 offset
loop 里 offset = minute 每帧执行 →
增量叠加自身 → 二次方加速（越转越快）
修法：连续 rAF 时钟
offset 只在 scrub/换档时重锚定，
render 由 now − start 驱动 → 严格匀速
教训
运动类需求要写可观测判据：

阶段 08 · 确定性录片

录屏卡顿 → Puppeteer 逐帧渲染：放弃模仿人手

两轮反馈 · 症状：卡顿 + 发软 —— 屏幕录制器的先天缺陷

实时滚动 → 帧间隔抖动 = 卡顿

CASE · 指令形态学

目标型
「帮我实现 GlowCard 组件，然后编制一个 demo 页面」

特征：名词 + 动词 + 验收载体

杠杆最大，一句顶十句普通反馈
校准型

特征：极短，依赖上下文
价值在方向——「先修组件」「静态动态分开」都是这类指令定义的
启示：模板库建好后，角色型指令是质量天花板——把「严苛大师 20 问」存成你的常用 prompt。

TECHNIQUE · 01

技法一：批量修复必须「失败即断言」

# 40 项修复的执行器：逐条断言，漏配即崩 def rep(old, new, n=1): c = s.count(old) assert c == n, f'MATCH {c}!={n}: {old[:80]}' return s.replace(old, new) rep('📅 <span id="dp-text">', '<span id="dp-text">') # emoji 移除
!
静默跳过 = 慢性毒药 —— 页面含 60 处关联值，一处漏改就是下一个 bug
✓
改生成物用脚本，不手改 —— 时间线/schema/批量修复全是 transform 脚本
✓
修复可重放 —— 脚本即文档：40 项怎么改的，代码自己会讲
